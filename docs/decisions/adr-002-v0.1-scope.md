# ADR-002: v0.1 Feature Scope

**状态**: 已采纳

**日期**: 2026-05-01

**背景**: 平台最终目标宏大（多算法、多环境、IRL/RLHF、多人协作），但必须渐进式交付。v0.1 需要找到一个"最小可演示价值"的切面。

**决策**: v0.1 锁定以下范围

| 维度 | 锁定值 |
|---|---|
| 环境 | MountainCar-v0 + CartPole-v1 |
| 算法 | PPO 唯一 |
| 奖励变体 | R0_sparse ~ R4_misleading（5 种） |
| 可视化 | 学习曲线 + 分量分解 + 健康度卡片 + 策略回放 |
| HPO | v0.1 不做（v0.2 引入 Optuna） |
| 数据库 | SQLite（单机零配置） |

**为什么选 MountainCar 而非 CartPole 作为主环境**:
CartPole 默认稠密奖励，PPO 在 50k 步内必收敛，无法观察稀疏 vs 稠密的差异。MountainCar 的稀疏奖励不加 shaping 几乎学不会，是奖励工程的"教科书演示场"。

**为什么 v0.1 只选 PPO**:
- PPO 同时支持离散和连续动作空间，cliff 到 v0.4 多算法时已有基础
- SB3 官方 RL Tips 建议：不确定时先 PPO
- PPO 训练日志天然区分 policy_gradient_loss / value_loss / entropy_loss / approx_kl

**后果**:
- (+) 100 人·小时可交付，2 人 × 4 周业余可完成
- (+) 每个 reward 变体都能在 MountainCar 上跑出明显差异
- (-) v0.1 不能演示多算法对比（需等 v0.4）
- (-) v0.1 不能演示 HPO（需等 v0.2）

**关联**: ADR-001 (tech stack), ADR-003 (reward wrapper order)
