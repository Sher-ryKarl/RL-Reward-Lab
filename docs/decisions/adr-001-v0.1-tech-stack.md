# ADR-001: v0.1 Technology Stack

**状态**: 已采纳

**日期**: 2026-05-01

**背景**: 项目需要从零搭建一个 RL 奖励函数可视化与自动调参平台，目标用户为 5–10 人实验室小团队。需要在开发速度和可扩展性之间取得平衡。

**决策**: 采纳 `技术栈选型.md` 方案 A（微调版）

| 层 | 选型 | 版本约束 |
|---|---|---|
| 前端框架 | React 18 + TypeScript 5 + Vite | React ≥18.3, TS ≥5.4 |
| 状态管理 | TanStack Query 5 + Zustand | — |
| 可视化 | Apache ECharts 5 (echarts-for-react) | 5.5+ |
| 后端框架 | FastAPI + Uvicorn + Pydantic v2 | FastAPI ≥0.135 |
| RL 训练 | SB3 2.3+ + sb3-contrib + imitation | — |
| 实验追踪 | MLflow 3.7+ (SQLite backend, 自托管) | — |
| 数据库 | SQLite → PostgreSQL v0.4+ | — |
| 实时推送 | SSE (FastAPI EventSourceResponse) | — |
| 任务调度 | asyncio.Semaphore + ProcessPoolExecutor | — |
| 包管理 | uv (Python) + npm (Node) | — |

**备选方案**:
- Ray Tune 替代 Optuna — 拒绝：v0.1 单机场景下 Ray Tune 有约 10× 调度开销；v0.4+ 再评估
- WebSocket 替代 SSE — 拒绝：训练曲线是单向 server→client 流；SSE 代码量是 WS 的 1/3，内建自动重连

**后果**:
- (+) 全 Python/TS 技术栈，小团队无需多语言学习成本
- (+) SQLite 零配置，新成员 30 分钟可跑起来
- (-) SQLite 单写入锁在 >50 实验/天时需要迁移 PostgreSQL
- (-) imitation 库要求 gymnasium<1.0，与最新 Gymnasium 主线存在版本约束

**关联**: ADR-002 (v0.1 scope), ADR-003 (reward wrapper order)
